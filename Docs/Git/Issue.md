# 이슈 규칙

> - 해당 파일은 개인 프로젝트 이슈에 대한 절대 규칙이다.
>
> - 이슈를 올리기 전 사용자에게 보고서를 제출하고, 승인 시 이슈를 올린다.

## 이슈 명 규칙

> 이슈 명은 "[타입] + 작업 내용" 으로 기입한다.

- 타입 종류
    - [Feat] : 새로운 것을 추가
    - [Fix] : 버그 수정
    - [Docs] : 문서 추가 및 수정
    - [Refactor] : 기능 추가나 버그 수정이 아닌 코드 구조 개선
    - [Asset] : 이미지, 사운드, 폰트 등 리소스 추가 및 교체
    - [Chore] : 프로젝트 세팅 같은 빌드 설정 또는 유니티 내의 세팅을 추가 및 변경

## 작업 내용 규칙

> 작업 내용은 최대한 간략하게 작성한다.

- 내용 작성은 직관적이게 작성한다.

|내용|작성법|
|---|---|
|스테이지1 맵 생성|Creat_Stage1_Map
|플레이어 움직임|Player_Movement
|UI 장비창 추가|UI_EquipWindow

## 이슈 내용 규칙

> 이슈 내용은 아래 양식에 맞게 작성한다.

- 양식
    ```markdown
    ## 기능 설명
    - 현재 브랜치에서 작업한 내용 기입

    ## 작업 중 발생한 오류 및 버그
    - 작엄 도중 발생한 오류 및 버그 기입
    - 발생한 오류 및 버그가 없다면 해당 내용을 없으면 빈칸으로 둔다.

    ## 해결 방법
    - 발생한 오류 및 버그 해결 방법 기입
    - 작업 도중 발생한 오류 및 버그가 없으면 해당 내용을 빈칸으로 둔다.

    ## 세부 작업 내용
    - [ ] 커밋1 내용 기입
    - [ ] 커밋2 내용 기입

    ## 일정
    - 시작일 : 브런치 생성 날짜 기입
    - 종료일 : 이슈 올린 날짜 기입
    - 브랜치 : 브랜치 명 기입
    ```

- 작업하지 않은 내용은 적지 않는다.

## 이슈 전 규칙

> 이슈를 올리기 전에 사용자에게 아래 양식으로 보고한다.

- 보고서 양식
    ```markdown
    - 시작일 : 브런치 생성 날짜 기입
    - 종료일 : 이슈 올린 날짜 기입
    - 이슈 명 : 현재 이슈 명 기입
    - 브랜치 명 : 현재 브랜치 명 기입
    - 작업한 내용 : 작업한 내용 기입 (커밋 수 만큼 기입)
    - 작업 도중 생긴 오류 및 버그 : 작업 중 생긴 오류 및 버그가 무엇인지, 어떤 이유로 생긴건지 기입
    - 오류 및 버그 해결 방법 : 위에 서술한 오류 및 버그를 어떻게 해결했는지 기입
    ```

- 작업하지 않은 내용은 보고서에 작성하지 않는다.
