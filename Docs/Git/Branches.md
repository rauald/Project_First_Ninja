# 브랜치 규칙

> - 해당 파일은 개인 프로젝트 브랜치에 대한 절대 규칙이다.
>
> - 브랜치 생성 전 사용자에게 보고하고, 승인 시 브랜치를 생성한다.

## 브랜치 명 규칙

> - 브랜치 명은 "타입/작업 내용" 으로 기입한다.
>
> - 브랜치 명은 소문자로 작성한다. (대문자를 사용하지 않는다.)

- 타입 종류
    - feat : 새로운 것을 추가
    - fix : 버그 수정
    - docs : 문서 추가 및 수정
    - refactor : 기능 추가나 버그 수정이 아닌 코드 구조 개선
    - asset : 이미지, 사운드, 폰트 등 리소스 추가 및 교체
    - chore : 프로젝트 세팅 같은 빌드 설정 또는 유니티 내의 세팅을 추가 및 변경

## 브랜치 내용 규칙

> - 브랜치 내용은 최대한 간략하게 작성한다.
>
> - 브랜치 내용은 소문자로 작성한다. (대문자를 사용하지 않는다.)
>
> - 특수 문자는 "/" 와 "-" 만 사용한다.

- 내용 작성은 직관적이게 작성한다.

|내용|작성법|
|---|---|
|스테이지 맵 생성|creat-stage-map
|플레이어 움직임|player-movement
|UI Window 작업|ui-window

## 브랜치 생성 전 규칙

> 브랜치 생성 전 사용자에게 아래 순서대로 질문한 뒤, 정리하여 보고 양식으로 보고하고, 승인을 받으면 브랜치를 생성한다.

- 질문 리스트
    1. 작업 내용 확인
    2. 브랜치 명 확인

- 보고 양식
    ```markdown
    - 브랜치 명 : 만들 브랜치 명 기입
    - 작업할 내용 : 해당 브랜치에서 작업할 내용 기입
    ```

- 지시한 작업 내용 외에는 작업할 내용에 추가로 적지 않는다.
- 브랜치 명을 약자로 하지 않는다.
