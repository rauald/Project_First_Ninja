# 프로젝트 Git 운영 설정

## 1. 저장소
- 저장소 위치: 프로젝트 루트
- 원격 호스팅: 미정
- 기본 remote: origin
- 기본 브랜치: 미정
- 작업 기준 브랜치: 미정
- 협업 형태: 개인 개발

기본 브랜치와 작업 기준 브랜치는
실제 저장소 및 사용자 의도를 확인한 뒤 기록한다.
main 또는 master라고 추측하지 않는다.

## 2. 작업 순서와 참조 문서
1. `Docs/Git/Branches.md`를 읽고 기준 브랜치와 작업 브랜치 이름을 확인한다. AI가 작업 브랜치를 생성할 수 있는 경우에는 실행 권한 절에 따라 승인받고, 현재 브랜치에서 AI 작업이 금지된 경우에는 사용자가 작업 브랜치로 전환한 뒤 진행한다.
2. 작업 브랜치에서 구현하고 이 문서의 검증 기준에 따라 확인한다.
3. 커밋이 승인된 경우 `Docs/Git/Commit.md`를 읽고 커밋한다.
4. 이슈 등록이 필요한 경우 `Docs/Git/Issue.md`를 읽고 요청된 시점에 등록한다.
5. push 또는 PR 생성이 필요한 경우 이 문서의 실행 권한을 확인한다. PR을 만들 때는 `Docs/Git/PR.md`를 읽는다.
6. 브랜치 삭제를 요청받으면 병합 여부와 삭제 대상을 확인한다.

## 3. 브랜치 전략
- 작업 브랜치는 확인된 작업 기준 브랜치에서 만든다.
- 현재 브랜치에서 사용 중인 AI의 작업이 금지되어 있으면 사용자에게 작업 브랜치로 전환해 달라고 요청하고 기다린다.
- 기준 브랜치에 직접 커밋하거나 push하지 않는다.
- 작업 브랜치에서 구현과 검증을 진행한다.
- 요청 범위에 포함된 경우에만 커밋, push, PR 생성으로 이어간다.
- 기준 브랜치 반영은 PR을 통해 진행한다.

## 4. AI 실행 권한
- 상태, 로그, diff 조회와 fetch는 사용 중인 AI의 프로젝트 지침에서 허용하는 범위에서 실행할 수 있다.
- 작업 브랜치 생성과 커밋은 대상과 범위를 알리고 승인받는다.
  이미 승인된 작업 범위에 해당 Git 작업이 포함되어 있으면 다시 승인받지 않는다.
- 사용자가 승인한 작업의 변경사항만 stage한다.
- 필수 검증을 통과한 변경만 커밋한다. 필수 검증을 실행할 수 없거나 통과하지 못하면
  변경을 보존하고 검증 상태를 보고한다.
- 작업 브랜치 push, 이슈 등록, PR 생성, 브랜치 삭제는 해당 작업을 명시적으로
  요청받거나 별도로 승인받은 경우에만 실행한다.
- PR은 사용자가 병합한다. 브랜치 삭제 전에는 병합 여부와 삭제 대상을 확인한다.
- 기존 변경사항 폐기, 강제 push, 공유 이력 재작성, 기존 커밋 amend,
  태그 생성 및 배포는 해당 작업에 대한 별도 명시가 필요하다.

## 6. 검증 기준

### 코드 변경
- 필수 검증:
  - [실제로 실행 가능한 검증 방법 작성]
- Unity 실행 검증:
  - [Play Mode에서 확인할 동작 작성]

### 문서만 변경
- 문서 내용과 경로, 링크, 규칙 충돌을 확인한다.

### 검증 환경이 없을 때
- 수행할 수 있는 검증과 불가능한 검증을 구분한다.
- 필수 검증을 수행하지 못했다면 완료로 단정하지 않는다.
- 현재 설정상 커밋 조건을 만족하지 못했다면 변경을 보존하고 보고한다.

## 7. PR

## 8. Unity 파일 추적
- Assets/와 해당 .meta 파일을 함께 관리한다.
- Packages/의 프로젝트 패키지 정의와 잠금 파일을 추적한다.
- ProjectSettings/를 추적한다.
- Library/, Temp/, Logs/, Obj/ 등 재생성 파일은 제외한다.
- 빌드 출력 폴더는 실제 출력 경로를 확인하고 제외한다.
- 생성되는 IDE 프로젝트 파일은 프로젝트 정책에 따라 제외한다.
- 기존 추적 파일은 .gitignore 추가만으로 추적 해제되지 않는다.
- 기존 파일의 추적 해제가 필요하면 영향을 설명하고 처리한다.

## 9. Git LFS
- 사용 여부: 미정
- 적용할 파일 종류: 미정
- 도입 전 확인 사항:
  - 원격 호스팅의 LFS 지원 여부
  - 저장 공간과 전송량 조건
  - 협업 환경에서의 사용 가능 여부
- 기존 이력을 LFS로 변환하는 작업은 별도로 결정한다.
