# 프로젝트 Git 운영 설정

## 1. 저장소
- 저장소 위치: 프로젝트 루트
- 원격 호스팅: 미정
- 기본 remote: origin
- 기본 브랜치: 미정
- 작업 기준 브랜치: 미정
- 협업 형태: 개인 개발

기본 브랜치와 작업 기준 브랜치는
실제 저장소 및 사용자 의도를 확인한 뒤 기록한다.
main 또는 master라고 추측하지 않는다.

## 2. 브랜치 전략
- 작업 기준 브랜치에서 작업 브랜치를 생성한다.
- 작업 브랜치에서 구현과 검증을 진행한다.
- PR을 통해 기준 브랜치에 반영한다.
- 기준 브랜치에 직접 커밋하거나 push하지 않는다.

### 브랜치 이름
- 기능: feat/짧은-영문-설명
- 수정: fix/짧은-영문-설명
- 구조 개선: refactor/짧은-영문-설명
- 문서: docs/짧은-영문-설명
- 유지보수: chore/짧은-영문-설명

### 예시
- feat/player-movement
- fix/duplicate-coin-collection
- docs/game-design

## 3. AI 실행 권한

### 매번 확인하지 않고 실행 가능
- Git 상태, 로그, diff 조회
- 기존 작업을 보존하는 작업 브랜치 생성
- 이번 작업 변경사항의 stage
- 필수 검증을 통과한 작업의 신규 커밋

### 현재 허용하지 않은 작업
- 원격으로 push
- PR 생성
- PR merge
- 브랜치 삭제
- 태그 생성과 배포

사용자가 현재 요청에서 위 작업을 명시적으로 지시하면
그 요청 범위에서 수행한다.

### 별도 명시가 필요한 작업
- 기존 변경사항 삭제
- reset --hard 또는 git clean
- 공유 이력 재작성
- force push
- 기존 커밋 amend

## 4. 커밋 메시지

### 형식
type(scope): 변경 내용

### 언어
- type과 scope는 영어로 작성한다.
- 제목과 본문 설명은 한국어로 작성한다.

### type
- feat: 새로운 기능
- fix: 오류 수정
- refactor: 기능 변화 없는 구조 개선
- docs: 문서 수정
- test: 테스트 추가 또는 수정
- chore: 설정과 유지보수
- perf: 성능 개선
- build: 빌드 구성 변경
- ci: 자동 검증 및 배포 구성 변경

### 예시
feat(player): 기본 이동과 방향 회전 구현
fix(items): 코인 중복 수집 방지
docs(git): 브랜치 운영 규칙 작성

### 본문
- 제목만으로 설명이 부족할 때 작성한다.
- 변경 이유와 중요한 영향을 설명한다.
- 실제로 수행하지 않은 검증을 작성하지 않는다.

## 5. 원격 동기화
- fetch 허용 여부: 허용
- pull 적용 방식: 미정
- 작업 브랜치 push: 사용자 요청 시 허용
- 기준 브랜치 직접 push: 허용하지 않음
- force push: 별도 명시적 요청 필요

## 6. 검증 기준

### 코드 변경
- 필수 검증:
  - [실제로 실행 가능한 검증 방법 작성]
- Unity 실행 검증:
  - [Play Mode에서 확인할 동작 작성]

### 문서만 변경
- 문서 내용과 경로, 링크, 규칙 충돌을 확인한다.

### 검증 환경이 없을 때
- 수행할 수 있는 검증과 불가능한 검증을 구분한다.
- 필수 검증을 수행하지 못했다면 완료로 단정하지 않는다.
- 현재 설정상 커밋 조건을 만족하지 못했다면 변경을 보존하고 보고한다.

## 7. PR
- 대상 브랜치: 미정
- 기본 생성 상태: Draft
- 제목과 본문 언어: 한국어
- 본문 양식: 공통 PullRequest.template.md
- merge 방식: 미정
- merge 실행 주체: 사용자

## 8. Unity 파일 추적
- Assets/와 해당 .meta 파일을 함께 관리한다.
- Packages/의 프로젝트 패키지 정의와 잠금 파일을 추적한다.
- ProjectSettings/를 추적한다.
- Library/, Temp/, Logs/, Obj/ 등 재생성 파일은 제외한다.
- 빌드 출력 폴더는 실제 출력 경로를 확인하고 제외한다.
- 생성되는 IDE 프로젝트 파일은 프로젝트 정책에 따라 제외한다.
- 기존 추적 파일은 .gitignore 추가만으로 추적 해제되지 않는다.
- 기존 파일의 추적 해제가 필요하면 영향을 설명하고 처리한다.

## 9. Git LFS
- 사용 여부: 미정
- 적용할 파일 종류: 미정
- 도입 전 확인 사항:
  - 원격 호스팅의 LFS 지원 여부
  - 저장 공간과 전송량 조건
  - 협업 환경에서의 사용 가능 여부
- 기존 이력을 LFS로 변환하는 작업은 별도로 결정한다.
