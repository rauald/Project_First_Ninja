# 커밋 규칙

> - 해당 파일은 개인 프로젝트 커밋에 대한 절대 규칙이다.
>
> - 커밋 올리기 전 사용자에게 보고서를 제출하고, 승인 시 커밋한다.

## 커밋 명 규칙

> 커밋 명은 "[커밋타입] + 커밋 내용" 으로 기입한다.

- 커밋타입 종류
    - [Feat] : 새로운 것을 추가
    - [Fix] : 버그 수정
    - [Docs] : 문서 추가 및 수정
    - [Refactor] : 기능 추가나 버그 수정이 아닌 코드 구조 개선
    - [Asset] : 이미지, 사운드, 폰트 등 리소스 추가 및 교체
    - [Chore] : 프로젝트 세팅 같은 빌드 설정 또는 유니티 내의 세팅을 추가 및 변경

## 커밋 내용 규칙

> 커밋 내용은 최대한 간략하게 작성한다.

- 내용 작성은 직관적이게 작성한다.

|내용|작성법|
|---|---|
|스테이지1 맵 생성|Creat_Stage1_Map
|플레이어 움직임|Player_Movement
|UI 장비창 추가|UI_EquipWindow

## 커밋 설명 규칙

> 커밋 설명은 어떤걸 추가했고, 어떤게 바뀌었는지를 작성한다.

- 작업한 모든 내용을 작성하지만, 100자 이내로 작성한다.
- 작업하지 않은 내용을 적지 않는다.

## 커밋 전 규칙

> 커밋을 하기 전 사용자에게 아래 양식으로 보고한다.

- 보고서 양식
    ```markdown
    - 브랜치 명 : 현재 브랜치 명 기입
    - 작업한 내용 : 작업한 내용 기입
    - 추가한 스크립트 (추가한 스크립트 수 만큼 아래 번호 추가)
        1. 추가한 스크립트 명 기입
            - 추가한 코드 (변수) 기입
            - 추가한 코드 (함수) 기입
            - 추가한 코드 (그 외) 기입
    - 삭제한 스크립트 (삭제한 스크립트 수 or 삭제한 코드가 있는 스크립트 수 만큼 아래 번호 추가)
        1. 삭제한 스크립트 명 or 삭제한 코드가 있는 스크립트 명 기입
            - 삭제한 코드 (변수) 기입
            - 삭제한 코드 (함수) 기입
            - 삭제한 코드 (그 외) 기입
    - 작업 도중 생긴 오류 및 버그 : 작업 중 생긴 오류 및 버그가 무엇인지, 어떤 이유로 생긴건지 기입
    - 오류 및 버그 해결 방법 : 위에 서술한 오류 및 버그를 어떻게 해결했는지 기입
    ```

- 작업하지 않은 내용은 보고서에 작성하지 않는다.
