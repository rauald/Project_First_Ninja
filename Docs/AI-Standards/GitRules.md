# Git 공통 작업 규칙

> 이 파일은 Git 공통 규칙으로 사용한다.

---

## 1. 작업 시작 전 확인
- Git 저장소인지 확인한다.
- 현재 브랜치와 작업 디렉터리 상태를 확인한다.
- 개인 프로젝트인지, 팀 프로젝트인지 사용자에게 물어본다.
    - 개인 프로젝트일 시 2번은 건너 뛴다.
    - 팀 프로젝티일 시 3번은 건너 뛴다.

## 2. 팀 프로젝트

> 팀 단위로 진행 할 시 팀 규칙을 우선시 한다.

- 커밋, 이슈, 브랜치, PR 양식은 팀 양식에 맞춰 진행한다.

## 3. 개인 프로젝트

> 개인 단위로 진행 할 시 각 파일을 참고한다.

- 작업 순서는 "브랜치 생성 - 커밋 - 이슈 생성 - PR - 브랜치 삭제" 이다.
- 커밋, 이슈, 브랜치, PR 양식은 아래 파일을 참고한다.
    - 커밋
        - Git\Commit.md
    - 이슈
        - Git\Issue.md
    - 브랜치
        - Git\Branches.md
    - PR
        - Git\PR.md

## 4. 완료 보고

> Git PR까지 완려 되었다면 최종 완료 보고를 한다.

- 완료 보고 양식은 아래를 참고한다.
    ```markdown
    - 브랜치 명 : PR 올린 브랜치 명 기입
    - 커밋 개수 :
        - 커밋 1 : 첫번째 커밋 명 기입 / 작업 내용
        - 커밋 2 : 두번째 커밋 명 기입 / 작업 내용
        - 커밋한 개수만큼 작성...
    - PR 명 : PR 명 기입
    - 주요 변경 내용 : 주요 변경 내용 기입
    - 추가한 스크립트 : 스크립트 명 기입
    - 삭제한 스크립트 : 스크리팁 명 기입
    - 검증 결과 : 검증 결과 기입
    - 남아 있는 변경사항 또는 해결하지 못한 문제
    ```

- 위 양식 외에 내용을 추가하지 않는다.
- 수행한 항목에 대해서만 보고한다.
